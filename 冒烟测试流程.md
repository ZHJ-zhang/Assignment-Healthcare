# 社区医院门诊管理系统 — 全套冒烟测试流程

> 版本：v1.0（对应 2026-10-25 系统状态）  
> 用途：每次构建 / 部署 / 迁移脚本执行后，快速验证核心链路是否"能跑通"。冒烟测试只验证主干 happy path 与少数关键边界，**不覆盖**性能、安全渗透、兼容性。  
> 优先级：P0 = 必须通过（阻断发布）；P1 = 应当通过；P2 = 锦上添花。



---

## 一、测试目标与范围

### 目标

- 验证系统启动后，**登录鉴权 → 患者 → 挂号 → 叫号 → 接诊 → 开方/开检查 → 收费 → 发药 → 完成就诊** 这条门诊主干能在各角色账号下跑通。
- 验证**权限（按钮级）与数据范围（医生"仅本人"）**&#x6CA1;有被放大或误收。
- 验证已知的几处"流程断链"已被打通（挂号费进收费单、检查费联动、退药挂退费单、预约取号不重复扣号、一医一人并发约束）。

### 范围与不在范围

| 在范围                                                                          | 不在范围                    |
| ---------------------------------------------------------------------------- | ----------------------- |
| 登录鉴权、患者管理、排班、挂号预约、候诊叫号、门诊接诊、处方、病历、检查、收费、药房、住院、健康档案、统计报表、系统管理（用户/角色/科室/菜单/字典） | 性能/压力测试；安全渗透；浏览器兼容性；移动端 |

### 模块冒烟优先级一览

- **P0**：登录、患者建档、排班、挂号（含挂号费单）、候诊叫号、接诊、开处方、收费、完成就诊。
- **P1**：开检查单、发药、退药退费、退号~~、住院主链路、健康档案、报表。~~
- **~~P2~~**~~：字典/菜单/审计、短信通知、消息中心。~~

## 三、角色与权限冒烟（P0/P1）

> 原则：页面初始化所需的下拉接口走 `/api/common/options/*`（**只要求登录、无角色权限**），所以"进得去页面"不该再 403；而业务写操作仍按角色 `@PreAuthorize` 严格校验。

### 3.1 按钮级权限（v-perm）冒烟

| 场景                                                                                | 期望                                                                                                                  |
| --------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------- |
| 医生(doc01) 访问 `/system/user/page`、`/system/dept/list`、`/drug/page`、`/patient/page` | **403**（不放宽管理员权限）                                                                                                   |
| 医生 访问 `/common/options/depts`、`/doctors`、`/drugs`、`/patients`                     | **200**，且仅返回必要字段（无身份证/手机号/密码）                                                                                       |
| 医生 进叫号大屏，看「叫号/过号/完成」按钮                                                            | 可见（已补 `registration:call`）                                                                                          |
| 收费员 进收费台，选患者带科室、拉处方/检查单                                                           | 可见（已补 patient:list / clinic:prescription:list / exam:apply:list / registration:schedule:list / charge:feeItem:list） |
| 药师 进药房，拉处方列表                                                                      | 可见（已补 clinic:prescription:list）                                                                                     |
| 护士 进住院登记，选床位                                                                      | 可见（已补 inpatient:bed:list）                                                                                           |

### 3.2 数据范围（医生"仅本人"）冒烟 — P0

doc01 的 `dataScope=4`（仅本人）。验证：

- 医生接诊队列 / 处方列表 / 病历 / 检查单 / 患者下拉：**只显示 `doctor_id=当前医生` 的记录**，看不到其他医生、其他科室。
- 打开别人（如 zz_docB）名下的处方详情 → **403「无权查看他人的处方」**。
- 替别人患者开方 / 开检查单 → **400 明确文案**（"该患者今天没有挂在你名下…"）。
- 开方时 `deptId` 一律取挂号记录上的科室，忽略前端传值。
- **换账号登录必须清下拉缓存**：医生 A 登录后切换为管理员（或反之），不能看到上一个账号的全院患者名单（`user.ts` 登录成功/reset 时调 `clearLookupCache()`）。

## 四、核心业务冒烟用例（P0 串联 happy path）

> 以下步骤以"一个真实患者走完一次门诊"为主线，账号标注在每一步。所有写接口返回应 **200**；任何 500 视为阻断。

### TC-01 登录鉴权（P0）

| 步骤 | 操作                                                 | 期望                                                                        |
| -- | -------------------------------------------------- | ------------------------------------------------------------------------- |
| 1  | `POST /api/system/user/login` {username, password} | 200，返回 `token` + `userInfo`（含 `permissions`、`roles`、`deptId`、`dataScope`） |
| 2  | 用 token 调 `GET /api/system/user/getInfo`           | 200，`permissions` 非空                                                      |
| 3  | 无 token 调任意业务接口                                    | 401                                                                       |
| 4  | 错误口令                                               | 业务拒绝；**不要拿真实账号反复试错**，否则 `healthcare:login:fail:*` 累计会锁号                   |

### TC-02 患者建档（P0）

| 步骤 | 操作                                   | 期望                                         |
| -- | ------------------------------------ | ------------------------------------------ |
| 1  | `patient:add` 新增患者（姓名/性别/生日/身份证/手机号） | 200，生成 `patient_no`                        |
| 2  | `patient:list` 查询该患者在列               | 可见                                         |
| 3  | 发卡 / 挂失 / 补卡 / 注销（patient:card:*）    | 状态流转正确：0 挂失→1 正常→2 注销；注销后余额清零、`card_no` 清空 |

### TC-03 排班与号源池（P0）

| 步骤 | 操作                                | 期望                   |
| -- | --------------------------------- | -------------------- |
| 1  | 管理员建/查排班（registration:schedule:*） | 排班存在且 `remain_num>0` |
| 2  | 记录某排班余号（如内科排班 2 余号 N）             | 作为后续扣号/退号还原基线        |

### TC-04 挂号 + 自动挂号费单（P0）★打通点

| 步骤 | 操作                                      | 期望                                                                               |
| -- | --------------------------------------- | -------------------------------------------------------------------------------- |
| 1  | `registration:add` 为该患者挂内科号（payType=微信） | 200，生成挂号记录 `REG...`，`queue_no` 有值，`status=0`（待就诊）                                |
| 2  | 查收费台该患者收费单                              | **自动生成一条 `visit_type=1`、金额=排班 `reg_fee`、pay_status=1 已支付的挂号费单**，明细 `itemType=6`  |
| 3  | 核实排班余号                                  | N→N-1（占号成功）                                                                      |
| 4  | 重复挂号（同患者同排班已有 0/1 挂号）                   | 400 拒绝"重复挂号"                                                                     |
| 5  | 退号 `registration:cancel`                | 挂号 `status=3`，收费单 pay_status→2（退费），余号 N-1→N；若该号来自预约，预约退回"待取号"且清空 registration_id |

### TC-05 预约 → 取号（P1）★打通点

| 步骤 | 操作                                                     | 期望                          |
| -- | ------------------------------------------------------ | --------------------------- |
| 1  | `appointment:add` 线上预约占号                               | 余号 M→M-1（预约占号）              |
| 2  | `appointment/{id}/checkin`（到院取号，复用 `registration:add`） | 生成挂号记录，**余号仍为 M-1（取号不再扣号）** |
| 3  | 同排班重复预约                                                | 400 拒绝                      |
| 4  | 取号后再取（幂等）                                              | 返回已有挂号，不重复扣号                |

### TC-06 候诊叫号（P0）★本轮修复重点

| 步骤 | 操作                                                            | 期望                                                                                                               |
| -- | ------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| 1  | `GET /api/registration/queue`（**无 deptId**，全科室；医生按数据范围只回自己名下） | 200，返回 `status IN (0,1)` 的号；**默认不再选空科室导致整屏空白**                                                                   |
| 2  | 患者姓名列                                                         | **正常显示姓名**（不再全 `-`；`String(id)` 比较修复）                                                                            |
| 3  | 医生(doc01) 点「叫号」按钮                                             | **按钮可见**（已补 `registration:call`）；点击后 `POST /api/registration/call/{id}`，挂号 `0→1`，生成 `biz_call_record`(callNo 递增) |
| 4  | 大屏"当前叫号"面板                                                    | 同步到 `status=1` 的号，30s 自动刷新（`setInterval(loadQueue, 30000)`）                                                      |
| 5  | 过号 `PUT .../pass`                                             | 挂号 `1→0`，号序退回队列可再叫                                                                                               |
| 6  | 完成 `PUT .../finish`                                           | 挂号 `1→2`（已完成），移出队列                                                                                               |
| 7  | 对 `status≠0` 的号叫号                                             | 400"该患者已在就诊中"（叫号只能对"待就诊"）                                                                                        |
| 8  | **并发约束**：医生已有 `status=1` 患者时再叫号 / 接诊                          | 400"该医生当前有患者正在就诊"（一医一人，避免绕过叫号直接接诊）                                                                               |

> 注意：种子数据里的挂号多为 `status=1`（就诊中），这类行在大屏**只显示过号/完成、不显示叫号**。要看叫号按钮，需一条 `status=0` 的挂号（现场挂一个即可）。

### TC-07 接诊（P0）

| 步骤 | 操作                                               | 期望                    |
| -- | ------------------------------------------------ | --------------------- |
| 1  | `clinic:visit:receive` 接诊（仅对 `status=0` 且是该医生名下） | 200，生成就诊记录，`status=1` |
| 2  | 接诊列表 `clinic:visit:list`                         | 能看到该患者；医生只看自己名下       |

### TC-08 开处方（P0）★状态机调整点

| 步骤 | 操作                                                                      | 期望                                 |
| -- | ----------------------------------------------------------------------- | ---------------------------------- |
| 1  | `clinic:prescription:add`（要求该患者有 `status=1` 的挂号；`doctorId/deptId` 取自挂号） | 200，处方 `status=0`（**待收费**，审核环节已取消） |
| 2  | 处方列表                                                                    | 可见，状态"待收费"                         |
| 3  | 未收费处方去收费台收费                                                             | 成功，`status=2`→可发药                  |
| 4  | 收费前作废                                                                   | `status=5`（已作废），维持终态               |

### TC-09 开检查单 + 检查费联动（P1）★打通点

| 步骤 | 操作                                     | 期望                                       |
| -- | -------------------------------------- | ---------------------------------------- |
| 1  | `exam:apply:add`（选诊疗项目带出 `amount`，可手改） | 200，检查单 `status=0`（待缴费），`amount` 落库      |
| 2  | 收费台勾选该检查单收费                            | 自动生成 `itemType=3` 明细；收费成功后申请单 `0→1`（待采样） |
| 3  | 未缴费直接采样 `exam:apply:sample`            | 400 拒绝                                   |
| 4  | "手工确认缴费"旧路径                            | 已封死，改"去收费"跳转                             |

### TC-10 收费与退费（P0/P1）

| 步骤 | 操作                                | 期望                                                 |
| -- | --------------------------------- | -------------------------------------------------- |
| 1  | 收费 `charge:add`（收挂号费/处方费/检查费，可合并） | pay_status=1 已支付；明细按 `itemType` 区分（6 挂号/1 处方/3 检查） |
| 2  | 退费 `charge:refund`                | pay_status→2，生成 `biz_refund`(status=2 已完成) 留痕      |
| 3  | 结算退费（住院）`refundSettlement`        | 仅 1→2，reason 必填，写 `refund_time/refund_reason`      |

### TC-11 药房：发药 / 退药（P1）★退药退费打通点

| 步骤 | 操作                                           | 期望                                                                                                     |
| -- | -------------------------------------------- | ------------------------------------------------------------------------------------------------------ |
| 1  | `drug:pharmacy:dispense`（处方须 `status=2` 已收费） | 处方 `2→3` 已发药；未收费发药 → 400"处方未收费"                                                                        |

| 4  | 重复退同一明细                                      | 400"已经退回过"                                                                                             |

## 八、验收标准

- **P0 用例 100% 通过**；P1 ≥ 90%；P2 不阻断。
- 全流程无 5xx；权限越界一律 403 / 400，且文案可读（不出现"服务器异常"模糊提示——已加 `NoResourceFoundException→404`）。
- 数据一致性：挂号费单 / 检查费单 / 处方费单金额与排班、明细一致；退药退费金额不超实收；号源余号无负数、无重复占号。
- 测试结束后**清理测试数据**（挂号、处方、收费单、退费单、退药明细、患者、登录日志），并把排班余号、库存还原基线；**停止临时验证实例（8081）**，8080 留给 IDEA。
